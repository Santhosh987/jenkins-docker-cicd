# Jenkins CI/CD Pipeline with Docker, GitHub, Amazon ECR & Amazon EKS

A hands-on DevOps project where I built an end-to-end CI/CD pipeline using Jenkins, Docker, GutHub, Amazon ECR, and Amazon EKS.

The pipeline automatically builds, tests, containerizes, and deploys a Node.js application whenever new code is pushed to GitHub.

## Project Overview

The application is a simple Node.js Express application running on port 3000.

Jenkins is hosted on an AWS EC2 instance and is responsible for running the CI/CD pipeline.

The pipeline performs the following:

- Checks out the latest code from GitHub
- Runs application tests
- Builds a Docker image
- Tags the image using the Jenkins build number
- Pushes the image to Amazon ECR
- Deploys the image to Amazon EKS
- Verifies the Kubernetes rollout

GitHub Webhooks are configured so that a push to the repository automatically triggers the Jenkins pipeline.

## CI/CD Pipeline

The Jenkins pipeline contains these stages:

1. Checkout
2. Test
3. Docker Build
4. ECR Login
5. Image Tagging
6. Image Push
7. Deploy to EKS

Each successful Jenkins build creates a uniquely tagged Docker image using the Jenkins `BUILD_NUMBER`.

Example:

jenkins-docker-cicd:10
jenkins-docker-cicd:11
jenkins-docker-cicd:12

This makes it easier to identify which Jenkins build produced a particular Docker image.

##### AWS Configuration
Region: ap-south-1
ECR Repository: jenkins-docker-cicd
EKS Cluster: jenkins-cluster
Node Group: jenkins-nodes
The EKS cluster uses managed worker nodes.
Jenkins accesses AWS services through an EC2 IAM role rather than storing AWS access keys inside the Jenkins configuration.

##### Kubernetes
The application is deployed using a Kubernetes Deployment with 2 replicas.
A Kubernetes LoadBalancer Service is used to expose the application.
The application runs on container port 3000.
The Kubernetes deployment is updated with the Docker image generated by the current Jenkins build.
Jenkins waits for the rollout to complete using:
kubectl rollout status deployment/jenkins-cicd-app

Kubernetes Deployment maintains rollout history, which allows a previous working version to be restored when required.
Example:
kubectl rollout history deployment/jenkins-cicd-app
kubectl rollout undo deployment/jenkins-cicd-app
